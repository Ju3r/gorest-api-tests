# GoREST API tests (Postman)

Postman-коллекция для API-автотестирования пользователей GoREST (`/public/v2/users`). Она разделена на одиночные проверки эндпоинтов и три сценария, которые последовательно проверяют создание, редактирование и удаление пользователя.

## Структура

```text
README.md
.gitignore
postman/
  GoREST API tests.postman_collection.json
  environments/
    GoREST API tests.environment.example.json
```

### API endpoints

Папка содержит отдельные запросы `GET /users`, `POST /users`, `PUT /users/{USER_ID}`, `DELETE /users/{USER_ID}` и `GET /users/{USER_ID}`. Для каждого проверяется ожидаемый HTTP-статус. Отправляйте эти запросы по одному через **Send**; для запросов по ID задайте `USER_ID`.

### Testing scenarios

В папке три сценария:

1. **Create User and verify** — генерирует уникальные данные, проверяет через `GET` по email, что пользователь ещё не существует, создаёт его, а затем проверяет наличие в отфильтрованном списке и ответ `GET` по ID.
2. **Edit User and verify** — проверяет существование созданного пользователя, обновляет его через `PUT` и отдельным `GET` подтверждает, что изменения сохранились.
3. **Delete User and verify** — проверяет, что пользователь существует, удаляет его и подтверждает `404` последующим `GET`.

Сценарии используют один ID: его сохраняет запрос `POST`, после чего ID читают сценарии редактирования и удаления. Для полного цикла запустите в Collection Runner **только верхнюю папку `Testing scenarios`**. Не запускайте коллекцию целиком: `API endpoints` предназначена для ручной отправки запросов. Если запускать только сценарий создания, созданная запись останется в GoREST до удаления.

## Переменные окружения

Импортируйте `postman/environments/GoREST API tests.environment.example.json` и выберите окружение **Main**.

| Переменная                   | Назначение                                                                                                                                |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `BASE_URL`                   | Базовый адрес API: `https://gorest.co.in/public/v2` — без `/users` и без Markdown-разметки.                                               |
| `BEARER_TOKEN`               | Токен GoREST для запросов с авторизацией. Укажите его локально только в **Current value**.                                                |
| `USER_ID`                    | ID вашей тестовой записи для одиночных запросов из `API endpoints`. В шаблоне оставлен пустым.                                            |
| `USER_GENDER`, `USER_STATUS` | Значения для одиночных `POST`/`PUT` запросов.                                                                                             |
| `SCENARIO_USER_*`            | Данные и ID, которыми сценарии обмениваются во время запуска. Email, имя, пол и статус для сценария создания генерируются перед запросом. |
| `SCENARIO_UPDATED_*`         | Новые имя и пол, используемые сценарием редактирования.                                                                                   |

## Запуск в Postman

1. Импортируйте `postman/GoREST API tests.postman_collection.json` и `postman/environments/GoREST API tests.environment.example.json`.
2. Выберите окружение **Main** и укажите действующий токен в `BEARER_TOKEN` → **Current value**.
3. В Collection Runner выберите верхнюю папку **Testing scenarios** и запустите её. Сценарии выполняются по порядку: создание → редактирование → удаление.
4. Убедитесь, что шаг удаления завершился статусом `204`, а финальный `GET` — статусом `404`.

Папка `API endpoints` предназначена для отдельных ручных запросов. Перед `PUT` или `DELETE` укажите `USER_ID` только своей тестовой записи. Запрос `DELETE` удаляет запись на публичном сервисе GoREST.
